# VYRA demo data and accounts

VYRA — Vulnerability, Yielded Response & Assistance. All data is fictional: an urban-flooding
scenario across ten Karachi areas.

## What is in it

- 80 emergency cases (demo mode; the Supabase seed uses 30 of them) across 10 areas, all urgency levels and statuses (new, investigating, assigned, resolved, cancelled), with 179 audit-history events
- 16 rescue teams, 34 supply records (boats, vehicles, first aid, medical, food, water), 11 shelters, 9 route hazards, 9 blocked roads
- 31 missions: 8 live (assigned, en route, on scene) and 23 completed, with the supplies each one holds
- 6 sign-in accounts

## Two ways to use it

**1. Demo mode (no Supabase).** Data lives in memory and resets when the server restarts.

    npm run dev:demo
    (or: VYRA_DATA_MODE=demo npm run dev   |   Windows PowerShell: $env:VYRA_DATA_MODE="demo"; npm run dev)

The sign-in page lists the accounts; the shared password is `VYRA-demo-1`. These accounts exist only in memory.

**2. Cloud Supabase.** The same data is stored in your project, with real sign-in. Follow
`SETUP_GUIDE.md`; in short:

    npm run db:setup -- --seed        (tables + this data + accounts)
    npm run db:seed                   (reset the data and accounts later)

The seed is `supabase/seed/vyra_full_seed.sql` (30 rows per table), generated by `scripts/generate-seed-30.mts` from the files below. Demo mode (`npm run dev:demo`) still uses the larger in-memory set described here; `supabase/vyra_complete_setup.sql` is the same seed plus the schema in one paste-and-run file.

## Changing the data

The source is `src/lib/db/demoSeed.ts` (cases), `demoOpsSeed.ts` (teams, supplies, shelters,
hazards, missions) and `src/lib/demoAccounts.ts` (accounts). After editing, run
`npm run db:seed:generate` to rebuild the SQL seed, then `npm run db:seed` to load it.
